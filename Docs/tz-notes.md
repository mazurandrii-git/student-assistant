# Конспект аналізу Технічного Завдання проєкту "Student Assistant"

## 1. Функціональні вимоги
- Перегляд переліку навчальних завдань.
- Додавання нового завдання (назва, дедлайн, пріоритет).
- Позначення завдання виконаним або невиконаним.
- Редагування та видалення завдань.
- Фільтрація та сортування за станом виконання чи пріоритетом.

## 2. Нефункціональні вимоги
- Кросплатформність: підтримка ОС Windows, macOS та Linux.
- Гетерогенність: використання декількох різних технологічних стеків.
- Модульність: незалежність розгортання кожного клієнтського модуля.
- Ведення історії змін та розробка виключно через Git/GitHub за моделлю GitHub Flow (гілки, PR, code review).

## 3. Модулі та технології
| Модуль | Технологія / Фреймворк | Тема курсу |
| :--- | :--- | :--- |
| Веб-клієнт | React | Тема 2 |
| Десктопний контейнер | Electron / NW.js | Тема 3 |
| Нативний клієнт | C++ / Qt | Тема 4 |
| Аналітичний модуль | Python / Flet | Тема 4 |

## 4. Формат обміну даними
- Єдиний спільний файл: `data/tasks.json` у корені репозиторію.
- Структура елемента JSON:
  - `id` (number) — унікальний ідентифікатор;
  - `title` (string) — назва завдання;
  - `completed` (boolean) — стан виконання (true/false);
  - `dueDate` (string) — дата у форматі YYYY-MM-DD;
  - `priority` (string) — пріоритет ("low", "medium", "high").

- Чи буде реалізовано автоматичне валідування JSON-структури при збереженні файлу з боку кожного клієнта?
